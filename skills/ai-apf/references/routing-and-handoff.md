# 路由与最小交接

## 分开作五个判断

1. **交互**：直接处理、有限澄清、深入形成问题。
2. **方法**：普通执行、知识解释、文献探索、数学推导、数据分析或科学问题形成，可按需组合。
3. **推理投入**：按当前步骤难度、错误代价和验证难度配置。优先使用已经足够的能力；确有收益再建议提高。核对目标环境实际可用选项，不硬编码易变的模型/套餐排序。
4. **执行环境**：依据真实的数据位置、工具、依赖、权限、计算量及可复现要求决定。对话同步不代表文件或程序环境同步。
5. **组织跨度**：依据是否持续积累资料、反复运行、形成多个结果或协作决定是否需要项目。复杂不自动意味着新项目；简单但长期重复的工作也可能值得项目化。

先在当前入口解决会改变下一步的最小疑问。迁移建议必须说明具体收益、转移哪些材料、由谁操作、怎样知道迁移完成。没有受支持的操作接口时提供最小交接文本，由用户在目标环境开启；不要虚构自动切换。

## 常见情形

| 情形 | 默认建议 | 何时调整 |
| --- | --- | --- |
| 输入齐全的单次绘图或格式修改 | 留在当前可完成的环境，直接处理 | 本地文件不可达或工具缺失时迁移 |
| 明确但困难的数学/物理推导 | 直接推导，必要时建议更强推理并安排独立核查 | 材料或符号缺失影响命题含义时澄清 |
| 大量本地数据、已有脚本与方法 | 优先相应 Codex 本地项目；先代表性小范围核查再批量运行 | 检查暴露科学定义或测量条件问题时重开该分支 |
| 没有数据的粗糙研究直觉 | 留在当前入口辨别关注，少量概念帮助或有限文献探索 | 明确下一步依赖本地材料或持续组织时迁移 |
| 从选题到多阶段分析与写作 | 优先复用已有项目；按具体产物划分线程 | 独立数据/协作/环境边界或组织收益确实时新建 |

这些是例子，不是封闭的升级条件。遇到具体实现、验证或资源困难，同样可以提高推理投入或调整环境。

## 独立 APF 对话何时有用

当问题形成持续占据较大注意力、需要反复比较框架，而执行另有材料和工具时，可开独立对话。短任务或边做边才能理解的问题，优先当前线程中的有限形成阶段。

独立对话需要可回传的当前状态，不能只交付一份润色后的任务说明。执行中发现新证据时更新相关依据与问题；不要要求全项目回到起点。

## 项目最小组织

先读相关现有约定和当前任务状态，再判断缺什么。通常只需能找到项目目标/范围、材料位置、当前问题与重要决定，以及实际生成的代码和结果。使用现有文档或线程记录；只有确有跨线程复用需要才新建记录。

项目记录是当前决策状态，不是不会出错的事实源。新线程无法读取旧线程时，把必要内容显式转交，不只说“参考之前讨论”。

## 最小交接

按任务需要填写，简单任务可以只有几句。不要为无关字段补空表。

多人目标或约束确实影响后续工作时，在选择理由或未决事项中保留：谁的目标、要求由谁提供、是否已确认、冲突点及需要谁决定。将研究者转述与相关方已确认的决定分开；交接整理不能把暂定建议变成共同同意，也不为普通任务增加必填的多人字段。

```text
原始关切 / 当前问题：
选择理由 / 重要未选方向及原因：
材料位置与版本 / 已授权范围：
已核实条件与检查结果：
推断、待检验假设与结论边界：
未决事项 / 哪些须由研究者选择：
下一步、产物、投入边界：
继续、停止或返回条件：
```

### 假设示例

原始关切：图像里的亮度结构为何看起来在移动。当前问题：先判断能否稳定测量图样位置随时间的变化；保留机制兴趣，尚未决定放弃。

选择理由：已有图像可能支持运动学描述，但目前没有足够证据把图样位移解释为等离子体输运。材料：用户指定序列及其元数据；尚未打开的文件不得写为已检查。

待核实：逐帧时间与曝光对应、几何变化、可重复识别的结构、测量误差。下一步：读取一段代表性序列和元数据，给出一个可复核的轨迹候选及条件判断；具体投入按用户已接受方案。

返回条件：若时标或结构身份不可辨识，先调整测量问题；若运动可信，再由研究者选择描述、方法验证或竞争机制比较。一个可见轨迹本身不构成真实输运或机制证据。
